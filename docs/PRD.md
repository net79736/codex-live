# PRD: YouTube Channel Insights

## 1. 제품 목표

YouTube 채널 URL을 입력하면 공개 채널 데이터를 수집하고 OpenAI로 분석해, 채널 운영자가 바로 실행할 수 있는 인사이트를 제공한다.

이 제품은 단순히 구독자 수, 총 조회수, 영상 수를 보여주는 도구가 아니다. 공개 지표를 사용자가 이해할 수 있는 진단으로 바꾸고, 그 진단을 다음 행동으로 연결하는 것이 핵심이다.

## 2. 제품이 풀어야 하는 문제

YouTube Studio와 공개 채널 페이지는 숫자를 보여준다. 하지만 많은 사용자는 그 숫자를 보고도 아래 질문에 답하지 못한다.

- 이 채널의 현재 포지션은 좋은가, 나쁜가?
- 강점은 콘텐츠 주제인가, 업로드 누적인가, 브랜드 톤인가?
- 지금 가장 먼저 고쳐야 할 문제는 무엇인가?
- 다음 영상, 제목, 채널 설명, 운영 방식 중 어디부터 손대야 하는가?
- 이 채널은 협업, 인수, 광고 제휴 대상으로 볼 만한가?

MVP의 핵심 가설은 다음과 같다.

채널 URL 하나만으로 받은 공개 데이터 기반 AI 진단이 사용자의 다음 행동을 정하는 데 충분히 유용하다면, 이 앱은 반복 사용 가치가 있다.

## 3. 핵심 사용자

### 3.1 채널 운영자

상황:
- 본인 채널을 운영하지만 지표 해석에 익숙하지 않다.
- 구독자 수, 조회수, 영상 수는 보지만 다음 액션을 정하지 못한다.
- 컨설팅을 받기 전 빠른 1차 진단을 원한다.

사용자가 얻고 싶은 답:
- 내 채널은 무엇이 강점인가?
- 성장에 방해되는 부분은 무엇인가?
- 이번 주에 무엇을 바꾸면 좋은가?

### 3.2 콘텐츠 마케터 또는 에이전시 담당자

상황:
- 여러 채널을 빠르게 검토해야 한다.
- 채널별 기본 상태와 개선 방향을 짧은 시간 안에 정리해야 한다.
- 내부 보고나 제안서의 초안이 필요하다.

사용자가 얻고 싶은 답:
- 이 채널을 어떻게 설명할 수 있는가?
- 개선 제안의 우선순위는 무엇인가?
- 클라이언트에게 어떤 액션을 제안해야 하는가?

### 3.3 제휴/인수 검토 담당자

상황:
- 특정 채널과의 협업, 광고, 인수 가능성을 빠르게 확인해야 한다.
- 비공개 Analytics 접근 없이 공개 데이터 기반의 1차 판단이 필요하다.

사용자가 얻고 싶은 답:
- 이 채널은 어떤 성격의 자산인가?
- 공개 지표만 봤을 때 매력과 리스크는 무엇인가?
- 추가 검토를 진행할 가치가 있는가?

## 4. 사용자에게 약속하는 결과

사용자는 분석 완료 후 아래 산출물을 얻어야 한다.

1. 채널의 기본 정체성
   - 채널명, 설명, 썸네일, 공개 지표를 통해 어떤 채널인지 빠르게 파악한다.

2. 짧은 진단 요약
   - “이 채널은 지금 어떤 상태인가”를 비전문가도 이해할 수 있는 문장으로 제공한다.

3. 강점
   - 사용자가 유지하거나 더 키워야 할 요소를 알려준다.

4. 개선 기회
   - 당장 성장을 막고 있을 가능성이 높은 문제를 알려준다.

5. 다음 액션
   - 추상적인 조언이 아니라, 이번 주에 실행 가능한 행동으로 제공한다.

## 5. 사용자 경험 원칙

- 첫 화면은 설명용 랜딩 페이지가 아니라 바로 분석을 시작하는 작업 화면이어야 한다.
- 사용자는 URL 입력, 로딩 상태, 결과 확인을 빠르게 끝낼 수 있어야 한다.
- 앱은 숫자를 나열하는 데서 끝나지 않고, 사용자가 다음 행동을 정할 수 있게 가이드해야 한다.
- 기본 지표는 판단의 근거이고, AI 인사이트는 해석과 행동 제안이다. 두 영역은 화면에서 분리한다.
- 오류가 발생하면 사용자가 고칠 수 있는 문제와 서비스 설정/외부 API 문제를 구분해서 알려야 한다.
- 실패 메시지는 원인과 다음 행동을 함께 말해야 한다.

## 6. 핵심 유저 스토리

### Story 1. 채널 URL 하나로 빠르게 진단받기

사용자로서, 나는 내 YouTube 채널 URL을 입력하고 싶다. 그래야 복잡한 설정 없이 채널 상태와 개선 방향을 빠르게 확인할 수 있다.

수용 기준:
- 사용자는 첫 화면에서 바로 URL을 입력할 수 있다.
- 지원하는 URL 형식은 `channelId`, `@handle`, `user` 형식이다.
- 입력이 비어 있거나 형식이 틀리면 분석 요청 전에 이유를 알려준다.
- 정상 URL이면 분석 요청이 시작되고 로딩 상태가 표시된다.

### Story 2. 분석 중 무엇이 일어나는지 이해하기

사용자로서, 나는 분석 중 앱이 멈춘 것처럼 보이지 않기를 원한다. 그래야 기다릴 가치가 있는지 판단할 수 있다.

수용 기준:
- 로딩 상태에서는 버튼이 비활성화된다.
- 화면은 “채널 확인 중”, “공개 지표 수집 중”, “인사이트 생성 중” 같은 단계형 문구를 보여준다.
- 단계 문구는 실제 내부 구현과 완전히 일치하지 않아도 되지만, 사용자가 현재 작업의 성격을 이해할 수 있어야 한다.
- 1분 이내 완료를 목표로 한다.

### Story 3. 숫자를 해석된 의미로 바꿔 보기

사용자로서, 나는 구독자 수나 조회수 같은 숫자만 보고 싶지 않다. 그래야 숫자가 내 채널에 어떤 의미인지 이해할 수 있다.

수용 기준:
- 결과 화면은 기본 지표와 AI 해석을 분리해서 보여준다.
- 채널명, 설명, 썸네일, 구독자 수, 총 조회수, 영상 수가 먼저 보인다.
- AI 요약은 한 문단으로 제공된다.
- 강점, 개선 기회, 다음 액션은 목록으로 제공된다.

### Story 4. 바로 실행할 다음 행동 정하기

사용자로서, 나는 분석 결과를 읽은 뒤 “무엇을 먼저 할지” 결정하고 싶다. 그래야 앱 사용이 단순한 감상으로 끝나지 않는다.

수용 기준:
- 다음 액션은 3개 이상 제공한다.
- 각 액션은 가능한 한 구체적인 동사로 시작한다.
- 액션은 채널 설명, 콘텐츠 주제, 업로드 전략, 제목/썸네일 방향처럼 사용자가 실제로 바꿀 수 있는 영역에 집중한다.
- MVP에서는 체크리스트 저장은 하지 않지만, 화면에서 복사하기 쉬운 문장 구조로 제공한다.

### Story 5. 실패했을 때 원인을 이해하기

사용자로서, 나는 분석이 실패했을 때 무엇을 고쳐야 하는지 알고 싶다. 그래야 같은 실패를 반복하지 않는다.

수용 기준:
- 잘못된 URL이면 URL 형식 문제를 알려주고 예시를 보여준다.
- API 키가 없으면 서비스 설정 문제라고 알려준다.
- YouTube API 실패와 OpenAI API 실패는 각각 다른 메시지로 구분한다.
- 사용자의 잘못이 아닌 경우 “다시 시도”를 제공한다.

## 7. 기본 유저 플로우

### 7.1 진입

사용자가 앱에 들어온다.

화면이 해야 할 일:
- 사용자가 설명을 읽기 전에 URL 입력 위치를 바로 찾을 수 있어야 한다.
- 제품명은 작게 보이더라도, 이 앱이 “YouTube 채널 분석 도구”라는 점은 즉시 드러나야 한다.
- 첫 화면은 랜딩 페이지가 아니라 작업 화면이어야 한다.

사용자 심리:
- “여기에 내 채널 주소를 넣으면 되나?”
- “로그인이나 설정이 필요한가?”

앱의 가이드:
- 입력 필드 placeholder는 실제 예시를 보여준다.
- 버튼은 `분석`처럼 짧게 둔다.
- 지원 URL 형식은 입력 필드 근처에 작게 안내한다.

### 7.2 URL 입력

사용자가 채널 URL을 붙여 넣는다.

화면이 해야 할 일:
- 앞뒤 공백은 자동으로 제거한다.
- 명백히 빈 값이면 요청하지 않는다.
- URL 형식이 지원되지 않으면 즉시 안내한다.

사용자 심리:
- “이 URL도 되는 건가?”
- “@handle 주소를 넣어도 되나?”

앱의 가이드:
- 실패 메시지는 “잘못되었습니다”가 아니라 “지원하는 YouTube 채널 URL을 입력하세요”처럼 다음 행동을 포함한다.
- 예시는 `https://www.youtube.com/@channelname` 형태로 보여준다.

### 7.3 분석 요청

사용자가 `분석`을 누른다.

시스템이 해야 할 일:
- Controller는 요청 검증과 응답 매핑만 담당한다.
- application 유스케이스가 URL 파싱, YouTube 조회, AI 분석 호출 순서를 조립한다.
- YouTube/OpenAI 호출은 포트 뒤에 둬서 테스트에서 대체 가능하게 한다.

사용자 심리:
- “요청이 들어갔나?”
- “얼마나 기다려야 하지?”

앱의 가이드:
- 버튼을 비활성화하고 중복 요청을 막는다.
- 로딩 상태를 입력 폼 근처에 보여준다.
- 가능하면 단계형 메시지로 기다리는 이유를 설명한다.

### 7.4 채널 기본 정보 확인

YouTube 공개 데이터가 정상 조회된다.

화면이 해야 할 일:
- 채널명과 썸네일을 먼저 보여줘서 사용자가 “내가 입력한 채널이 맞다”고 확인하게 한다.
- 구독자 수, 총 조회수, 영상 수는 같은 구조로 배치한다.
- 숫자는 locale formatting을 적용한다.

사용자 심리:
- “내 채널이 맞네.”
- “기본 지표는 이렇구나.”

앱의 가이드:
- 지표는 판단의 근거이고, 결론은 인사이트 영역에서 제공한다.
- 지표와 AI 조언이 섞이지 않게 분리한다.

### 7.5 AI 인사이트 확인

OpenAI 분석 결과가 생성된다.

화면이 해야 할 일:
- 가장 먼저 한 문단 요약을 보여준다.
- 그 다음 강점, 개선 기회, 다음 액션을 보여준다.
- 항목은 너무 길지 않게 유지하되, 실행 의미가 분명해야 한다.

사용자 심리:
- “내가 뭘 잘하고 있지?”
- “뭘 먼저 고쳐야 하지?”
- “이 조언이 내 채널에 맞는 말인가?”

앱의 가이드:
- 요약은 판단의 큰 방향을 잡아준다.
- 강점은 유지할 것을 알려준다.
- 개선 기회는 문제를 알려준다.
- 다음 액션은 사용자가 앱을 닫은 뒤 할 일을 알려준다.

### 7.6 결과 이후 행동

사용자가 분석 결과를 읽고 다음 행동을 정한다.

MVP에서 지원하는 행동:
- 다른 채널 URL을 입력해 다시 분석한다.
- 결과 문장을 복사하거나 화면에서 참고한다.
- 실패했으면 입력을 고치거나 다시 시도한다.

MVP에서 지원하지 않는 행동:
- 분석 이력 저장
- 로그인
- PDF 내보내기
- 팀 공유
- 경쟁 채널 자동 비교

## 8. 화면 상태 정의

### 8.1 Empty

사용자가 아직 분석하지 않은 상태.

필수 요소:
- URL 입력 필드
- 분석 버튼
- 지원 URL 형식 안내
- 결과 영역의 빈 상태

빈 상태 메시지 방향:
- “채널 URL을 입력하면 공개 지표와 AI 인사이트가 표시됩니다.”

### 8.2 Validating

사용자가 입력했지만 요청 전 검증이 필요한 상태.

필수 요소:
- 입력값 유지
- 검증 오류가 있으면 입력 필드 아래 표시

### 8.3 Loading

분석 요청이 진행 중인 상태.

필수 요소:
- 비활성화된 버튼
- 로딩 문구
- 기존 결과가 있다면 새 분석 중임을 명확히 표시

### 8.4 Success

분석이 성공한 상태.

필수 요소:
- 채널 기본 정보
- 핵심 지표
- AI 요약
- 강점
- 개선 기회
- 다음 액션
- 다른 URL을 입력해 다시 분석할 수 있는 흐름

### 8.5 Error

분석이 실패한 상태.

필수 요소:
- 오류 원인
- 사용자가 할 수 있는 다음 행동
- 입력값 유지
- 다시 시도 또는 수정 유도

## 9. 오류 플로우

### 9.1 빈 입력

상황:
- 사용자가 아무것도 입력하지 않고 분석을 누른다.

메시지 방향:
- “YouTube 채널 URL을 입력하세요.”

사용자에게 줄 다음 행동:
- 입력 필드에 커서를 유지한다.

### 9.2 지원하지 않는 URL

상황:
- 영상 URL, 재생목록 URL, Shorts URL, 일반 웹사이트 URL을 입력한다.

메시지 방향:
- “채널 URL만 분석할 수 있습니다. `https://www.youtube.com/@channelname` 형식으로 입력하세요.”

사용자에게 줄 다음 행동:
- 지원 예시를 보여준다.

### 9.3 채널을 찾을 수 없음

상황:
- URL 형식은 맞지만 YouTube에서 채널을 찾지 못한다.

메시지 방향:
- “해당 채널을 찾을 수 없습니다. 주소가 정확한지 확인하세요.”

사용자에게 줄 다음 행동:
- 사용자가 입력값을 수정할 수 있게 유지한다.

### 9.4 API 키 누락

상황:
- 서버에 `YOUTUBE_API_KEY` 또는 `OPENAI_API_KEY`가 없다.

메시지 방향:
- “서비스 설정이 완료되지 않아 분석할 수 없습니다.”

사용자에게 줄 다음 행동:
- 일반 사용자가 고칠 수 없는 문제임을 분명히 한다.
- 개발/운영 환경에서는 누락된 키를 로그나 내부 메시지로 식별 가능해야 한다.

### 9.5 외부 API 실패

상황:
- YouTube API 또는 OpenAI API가 실패한다.

메시지 방향:
- YouTube 실패: “YouTube에서 채널 정보를 가져오지 못했습니다.”
- OpenAI 실패: “채널 정보는 확인했지만 인사이트 생성에 실패했습니다.”

사용자에게 줄 다음 행동:
- 다시 시도 버튼을 제공한다.
- YouTube 정보까지 성공한 경우, 향후에는 기본 지표만이라도 보여줄 수 있다. MVP에서는 전체 실패로 처리해도 된다.

## 10. MVP 기능 요구사항

### 10.1 입력

지원 URL:
- `https://www.youtube.com/channel/{channelId}`
- `https://www.youtube.com/@{handle}`
- `https://www.youtube.com/user/{username}`

입력 처리:
- 앞뒤 공백은 제거한다.
- 빈 값은 요청하지 않는다.
- 지원하지 않는 URL은 명확한 오류로 응답한다.

### 10.2 채널 데이터 수집

수집 항목:
- 채널명
- 설명
- 썸네일
- 구독자 수
- 총 조회수
- 영상 수

제약:
- 공개 데이터만 사용한다.
- YouTube OAuth는 사용하지 않는다.
- 비공개 Analytics 데이터는 수집하지 않는다.

### 10.3 AI 인사이트 생성

생성 항목:
- AI 요약
- 강점
- 개선 기회
- 다음 액션

품질 기준:
- 요약은 한 문단으로 제공한다.
- 강점, 개선 기회, 다음 액션은 서로 중복되지 않아야 한다.
- 다음 액션은 3개 이상 제공한다.
- 조언은 일반론처럼 보이지 않고 채널 기본 정보와 연결되어야 한다.

### 10.4 결과 제공

제공 방식:
- 웹 화면
- JSON API

화면 기준:
- 데스크톱에서는 채널 기본 정보와 인사이트를 2컬럼으로 비교 가능하게 배치한다.
- 모바일에서는 입력 폼, 채널 정보, 인사이트 순서의 1컬럼으로 배치한다.
- 숫자는 locale formatting을 적용한다.

## 11. MVP 구현 우선순위

### Slice 1. URL 입력과 검증

목표:
- 사용자가 첫 화면에서 채널 URL을 입력하고, 잘못된 입력은 명확히 안내받는다.

포함:
- 입력 폼
- 지원 URL parser
- 잘못된 URL 오류
- Controller validation
- URL parser 단위 테스트

### Slice 2. 공개 채널 데이터 조회

목표:
- 정상 URL로 YouTube 채널 기본 정보를 가져온다.

포함:
- `YoutubeChannelClient` 포트
- YouTube adapter
- 채널 기본 정보 모델
- API 키 누락 오류
- adapter를 fake로 대체한 application 테스트

### Slice 3. AI 인사이트 생성

목표:
- 채널 기본 정보를 바탕으로 요약, 강점, 개선 기회, 다음 액션을 생성한다.

포함:
- `ChannelInsightClient` 포트
- OpenAI adapter
- 인사이트 결과 모델
- OpenAI 실패 오류
- fake insight client 기반 use case 테스트

### Slice 4. 결과 화면

목표:
- 사용자가 숫자와 인사이트를 한 화면에서 이해하고 다음 행동을 정한다.

포함:
- Empty, Loading, Success, Error 상태
- 지표 formatting
- 인사이트 목록 렌더링
- 모바일 1컬럼, 데스크톱 2컬럼

### Slice 5. 오류 경험 정리

목표:
- 실패 상황에서도 사용자가 원인과 다음 행동을 이해한다.

포함:
- URL 오류
- 채널 없음
- API 키 누락
- YouTube 실패
- OpenAI 실패
- Controller 예외 매핑 테스트

## 12. MVP 제외 사항

- YouTube OAuth 로그인
- 비공개 Analytics 데이터 수집
- 사용자 계정/권한
- 분석 이력 저장
- 결제
- 경쟁 채널 자동 비교
- 영상별 상세 분석
- PDF/보고서 내보내기
- 팀 공유

이 제외 사항은 기능이 중요하지 않아서가 아니라, 첫 번째 검증 질문을 흐리지 않기 위해 제외한다.

## 13. 성공 기준

정량 기준:
- 사용자가 채널 URL 입력 후 1분 이내 결과를 본다.
- 정상 URL 분석 성공률을 로컬/개발 환경에서 반복 검증할 수 있다.
- 잘못된 URL, API 키 누락, 외부 API 실패가 서로 다른 오류로 반환된다.

정성 기준:
- 사용자가 결과를 읽고 “그래서 다음에 뭘 하지?”라고 묻지 않아야 한다.
- 강점, 개선 기회, 다음 액션이 서로 중복되지 않아야 한다.
- 조언이 일반론처럼 보이지 않고 채널 기본 정보와 연결되어야 한다.
