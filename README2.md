• 정리했습니다.

  - docs/PLAN.md는 삭제했습니다.
  - 상세 유저 스토리, 유저 플로우, 화면 상태, 오류 플로우, MVP slice를 전부 docs/PRD.md에 흡수했습니다.
  - README.md에 “Codex가 docs/를 언제 읽는지”를 추가했습니다.

  핵심은 이겁니다.

  AGENTS.md는 Codex가 기본 규칙으로 보는 문서입니다. 반면 docs/는 매 대화마다 자동으로 전부 읽는 폴더는 아닙니다. Codex가 docs/를 읽는 경우는
  보통 네 가지입니다.

  1. 사용자가 “docs 먼저 읽고 해줘”라고 요청할 때
  2. 큰 기능 구현, 설계, UI, 리뷰처럼 문서 기준이 필요하다고 판단될 때
  3. scripts/execute.py를 쓸 때, 이 스크립트가 AGENTS.md와 docs/*.md를 프롬프트에 넣을 때
  4. harness / harness-review skill을 쓸 때

  그래서 항상 지켜야 하는 짧은 규칙은 AGENTS.md, 제품 의도와 상세 기획은 docs/PRD.md, 구조는 docs/ARCHITECTURE.md, 결정 이유는 docs/ADR.md, UI
  방향은 docs/UI_GUIDE.md에 두는 게 맞습니다.

  문서 작업이라 테스트는 실행하지 않았습니다.

---

결론부터 말씀드리면, 질문하신 AGENTS.md, Skills(스킬), Hooks(훅) 이 3가지가 Codex 에이전트 개발 및 프로젝트 커스터마이징의 가장 핵심적인 3대 기둥이 맞습니다! 이것만 제대로 파악해도 나만의 컨텍스트를 완벽히 통제하는 에이전트 환경을 만들 수 있습니다.

하지만 실제 에이전트를 더 강력하고 외부 시스템과 유연하게 연결하려면, 이 3개 외에 MCP(Model Context Protocol)라는 개념을 반드시 하나 더 알아두셔야 합니다.

각 개념이 왜 필요하고, 어떻게 유기적으로 맞물리는지 명확하게 정리해 드릴게요.

🛠️ Codex 커스터마이징의 3대 핵심 (알고 계신 것)
각 도구는 "AI에게 규칙을 언제, 어떻게 적용할 것인가?"에 따라 역할이 명확히 나뉩니다.

1. AGENTS.md (지속적인 가이드라인)
역할: 해당 프로젝트(리포지토리) 전체에 적용되는 영구적인 컨텍스트이자 지침서입니다. (클로드 진영의 CLAUDE.md와 같은 역할)

특징: 세션이 시작될 때 최상위에서 작동하며, AI가 코딩할 때 절대 어기면 안 되는 코딩 컨벤션, 패키지 구조, 핵심 아키텍처 규칙을 주입합니다.

팁: 너무 길어지면 토큰 낭비가 심하므로, 프로젝트의 핵심 규칙 위주로 콤팩트하게 작성해야 합니다.

2. Skills (재사용 가능한 워크플로우 / AI의 능력)
역할: 특정 상황이나 명령어가 들어왔을 때 실행할 수 있는 'AI의 특수 스킬 팩'입니다.

구성: 디렉토리 구조로 되어 있으며, 핵심 설명 파일인 SKILL.md와 선택적인 실행 스크립트로 이루어집니다.

특징: 평소에는 메타데이터만 갖고 있다가, 사용자가 명시적으로 부르거나($스킬명 또는 /skills), 사용자의 요청이 스킬의 설명과 일치할 때(자연어 매칭) 필요한 순간에만 명세(SKILL.md)를 컨텍스트에 로드합니다. AI의 추론(Reasoning) 능력이 필요한 반복 작업에 적합합니다.

3. Hooks (결정론적 자동화 / 이벤트 트리거)
역할: 특정 이벤트가 발생했을 때 무조건 자동으로 실행되는 스크립트입니다.

특징: 스킬이 'AI의 생각과 판단'을 거쳐 실행된다면, 훅은 '100% 기계적인 자동화(Deterministic)'입니다. 파일이 저장되거나, 코드가 생성된 직후, 혹은 에이전트가 작업을 종료하기 직전(Pre-stop)에 트리거됩니다.

활용: 코드 포매터(Linter) 실행, JSON 스키마 검증, 테스트 수트 자동 실행 등 "AI에게 물어볼 필요도 없이 무조건 검증해야 하는 영역"을 처리할 때 씁니다.

🚀 완벽한 에이전트를 위해 '이것'까지 알면 끝납니다
이 3가지를 마스터했다면, 마지막 퍼즐 조각은 MCP (Model Context Protocol) 입니다.

MCP가 왜 필요한가요?

AGENTS.md, Skills, Hooks는 기본적으로 로컬 워크스페이스(코드 저장소) 안에서의 규칙과 동작을 제어합니다.

하지만 개발을 하다 보면 슬랙(Slack)에 알림을 보내거나, 지라(Jira) 티켓을 생성하거나, 데이터베이스에 직접 쿼리를 날려 로그를 확인해야 할 때가 있습니다.

MCP는 Codex가 로컬 컴퓨터를 넘어 외부 도구, API, 타사 서비스들과 안전하게 데이터를 주고받을 수 있도록 연결해 주는 개방형 프로토콜 표준입니다.

💡 한눈에 보는 역할 분담 요약
새로운 에이전트 환경을 구축하신다면 아래 구조를 머릿속에 그리시면 편합니다.

"우리 팀 Java/Spring 컨벤션 지켜줘" ➡️ AGENTS.md에 작성

"코드 생성되면 무조건 컴파일 테스트랑 린터 돌려" ➡️ Hooks로 강제 자동화

"특정 도메인의 복잡한 보일러플레이트 코드나 마이그레이션 로직 짜줘" ➡️ Skills로 묶어서 실행

"지금 에러 로그 분석해서 사내 슬랙 채널에 공유해줘" ➡️ MCP 연동으로 외부 시스템 제어

질문하신 대로 AGENTS.md, skills, hooks를 제대로 이해하고 있다면 이미 Codex 개발의 90% 이상을 파악하신 게 맞습니다! 여기에 외부 연동을 위한 MCP 구조만 가볍게 얹어주시면 완벽한 커스텀 에이전트를 만드실 수 있습니다.
